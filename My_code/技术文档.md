# ros2 学习技术文档

## 0.0快速体验
学习目标：编写ros2程序输入hello world
准备：实现工作空间的创建与编译
```
mkdir -p ws00_helloworld/src #创建工作空间以及子级目录 src，工作空间名称可以自定义
cd ws00_helloworld #进入工作空间
colcon build #编译

cd src
ros2 pkg create pkg01_helloworld_cpp --build-type ament_cmake --dependencies rclcpp --node-name helloworld
```
流程简介：
1. 创建功能包；ros2 pkg create 包名 --build-type 构建类型 --dependencies 依赖列表 --node-name 可执行程序名称
2. 编辑源文件；
3. 编辑配置文件；实际使用当中经常需要自己编辑配置文件：
所使用的配置文件主要有两个，分别是功能包下的package.xml与CMakeLists.txt
4. 编译；colcon build
5. 执行。ros2 run 功能包 可执行程序 参数

目录结构：
WorkSpace --- 自定义的工作空间。
    |--- build：存储中间文件的目录，该目录下会为每一个功能包创建一个单独子目录。
    |--- install：安装目录，该目录下会为每一个功能包创建一个单独子目录。
    |--- log：日志目录，用于存储日志文件。
    |--- src：用于存储功能包源码的目录。
        |-- C++功能包
            |-- package.xml：包信息，比如:包名、版本、作者、依赖项。
            |-- CMakeLists.txt：配置编译规则，比如源文件、依赖项、目标文件。

            |-- include：头文件目录。
            |-- msg：消息接口文件目录。
            |-- srv：服务接口文件目录。
            |-- action：动作接口文件目录。
        |-- Python功能包
            |-- package.xml：包信息，比如:包名、版本、作者、依赖项。
            |-- setup.py：与C++功能包的CMakeLists.txt类似。
            |-- setup.cfg：功能包基本配置文件。

## 一、ros2的通信机制
### 1.1 通信机制简介
节点：通信的对象的构建，一般一个节点对应某一单一的功能模块，比如雷达驱动节点负责发布雷达消息，摄像头驱动节点负责发布摄像头消息。
话题：具有相同话题的节点可以关联在一起。
通信模型：ros2中有四种通信模型，如下：
- 话题通信
单向通信模型，发布方发布数据，订阅方订阅数据。
- 服务通信
一种基于请求响应的通信模型，客户端发送请求响应到服务端，服务端响应结果到服务端。
- 动作通信
是一种带有连续反馈的通信模型，在通信双方中，客户端发送请求数据到服务端，服务端响应结果给客户端，但是在服务端接收到请求到产生最终响应的过程中，会发送连续的反馈信息到客户端。
- 参数服务
是一种基于共享的通信模型，在通信双方中，服务端可以设置数据，而客户端可以连接服务端并操作服务端数据。、

### 1.2 话题通信
#### 1.2.1 话题通信简介
一个节点发送消息，一个节点订阅消息。数据发布对象称为发布方，数据订阅对象称之为订阅方，发布方和订阅方通过话题相关联，发布方将消息发布在话题上，订阅方则从该话题订阅消息，消息的流向是单向的。
作用：
话题通信一般应用于不断更新的、少逻辑处理的数据传输场景。
消息接口：
1. ros2中通过std_msgs封装了一些原生的数据类型
2. ros2中海定义类许多标准类型
3. 自定义消息类型
#### 1.2.2 话题通信实践
案例需求：
- 需求1：写话题通信实现，发布方以某个频率发布一段文本，订阅方订阅消息，并输出在终端。
- 需求2：编写话题通信实现，发布方以某个频率发布自定义接口消息，订阅方订阅消息，并输出在终端。
案例分析：
有三个元素需要关注：
1. 发布方
2. 订阅方
3. 消息载体
流程简介
编写发布方实现；
编写订阅方实现；
编辑配置文件；
编译；
执行。

### 1.3 服务通信
#### 1.3.1 案例需求
编写服务通信，客户端可以提交两个整数到服务端，服务端接收到整数数据后请求并分析两个整数求和，然后把结果反应给客户端

#### 1.3.2 案例分析
主要关注三个要素
1. 客户端
2. 服务端
3. 消息载体

#### 1.3.3 流程简介
先自定义服务接口，接口准备完毕后，服务实现主要步骤如下：
- 编写服务端实现
- 编写客户端实现
- 编辑配置文件
- 编译
- 执行

1. 创建并编辑.srv文件

```

```

2. 配置编辑文件

package.xml不用编辑，这个一般是声明依赖哪些功能包而不是有哪些接口文件，通用接口适用于.msg .srv .action所以不需要

在CMakeLists.txt中增加
rosidl_generate_interfaces(${PROJECT_NAME}
    "msg/Student.msg"
    "srv/AddInts.srv"
)

只有接口采用了其他功能包的消息类型，才需要在此修改package.xml

添加内容的格式是：
find_package()
rosidl_generate_interfaces(${PROJECT_NAME})
