## 问题 1：编译时提示 `No module named 'catkin_pkg'`

### 问题现象

在工作空间中执行 `colcon build` 时，出现以下错误：

```text
ModuleNotFoundError: No module named 'catkin_pkg'
```

关键的报错信息为：

```text
execute_process(/home/luvbot-2/miniconda3/bin/python3
  /opt/ros/humble/share/ament_cmake_core/cmake/core/package_xml_2_cmake.py ...)
```

### 问题原因

ROS 2 的 `ament_cmake` 在处理 `package.xml` 时，会运行 `package_xml_2_cmake.py`。该脚本需要导入 `catkin_pkg`：

```python
from catkin_pkg.package import parse_package_string
```

当前 CMake 选中的是 Miniconda 的 Python：

```text
/home/luvbot-2/miniconda3/bin/python3
```

但 `catkin_pkg` 实际安装在系统 Python 环境中：

```text
/usr/lib/python3/dist-packages/catkin_pkg
```

Miniconda Python 不会默认读取系统 Python 的模块，因此报错。另外，CMake 已经在 `CMakeCache.txt` 中缓存了 Miniconda Python 的路径，只退出 Conda 不一定能消除问题。

### 解决方法

进入工作空间，退出 Conda，并加载 ROS 2 Humble 环境：

```bash
cd /home/luvbot-2/ros2_learning/My_code/ws00_helloworld
conda deactivate
source /opt/ros/humble/setup.bash
which python3
```

`which python3` 应该输出：

```text
/usr/bin/python3
```

如果仍然指向 Miniconda，继续执行 `conda deactivate`，直到 Python 指向 `/usr/bin/python3`。

清理已经记录了错误 Python 路径的构建缓存，然后重新编译：

```bash
rm -rf build install log
colcon build --symlink-install
source install/setup.bash
```

也可以临时强制 CMake 使用系统 Python：

```bash
colcon build \
  --cmake-clean-cache \
  --cmake-args -DPython3_EXECUTABLE=/usr/bin/python3
```

但 Conda 还可能影响 `fmt` 等其他 CMake 依赖，因此推荐退出 Conda 并完整清理构建缓存。不建议优先在 Miniconda Python 3.13 中单独安装 `catkin_pkg`，因为 ROS 2 Humble 在 Ubuntu 22.04 上通常与系统 Python 3.10 配合使用，混用环境可能引发其他依赖或 ABI 兼容性问题。

## 问题 2：为什么 `ros2 run pkg01_helloworld_cpp helloworld` 能够运行节点

### 命令格式

`ros2 run` 的基本格式是：

```bash
ros2 run <功能包名称> <可执行文件名称>
```

所以：

```bash
ros2 run pkg01_helloworld_cpp helloworld
```

其中：

- `pkg01_helloworld_cpp` 是功能包名称；
- `helloworld` 是编译后生成的可执行文件名称。

### 1. 功能包名称的来源

`package.xml` 中定义了功能包名称：

```xml
<name>pkg01_helloworld_cpp</name>
```

`CMakeLists.txt` 中也定义了相同的项目名称：

```cmake
project(pkg01_helloworld_cpp)
```

因此，`ros2 run` 的第一个参数为 `pkg01_helloworld_cpp`。

### 2. 可执行文件名称的来源

`CMakeLists.txt` 中的以下配置：

```cmake
add_executable(helloworld src/helloworld.cpp)
```

表示使用 `src/helloworld.cpp` 源文件编译生成名为 `helloworld` 的可执行文件。

```text
src/helloworld.cpp
        ↓ 编译
helloworld
```

`ros2 run` 的第二个参数来自 `add_executable()` 的第一个参数，而不是节点名称。

### 3. ROS 2 如何找到可执行文件

`CMakeLists.txt` 中的安装规则为：

```cmake
install(TARGETS helloworld
  DESTINATION lib/${PROJECT_NAME})
```

`${PROJECT_NAME}` 的值是 `pkg01_helloworld_cpp`，因此 `colcon build` 编译完成后，可执行文件会被安装到：

```text
install/pkg01_helloworld_cpp/lib/pkg01_helloworld_cpp/helloworld
```

编译完成后需要加载工作空间：

```bash
source install/setup.bash
```

该脚本会把当前工作空间注册到 ROS 2 环境中。执行 `ros2 run` 时，ROS 2 先找到 `pkg01_helloworld_cpp` 功能包，再到其 `lib/pkg01_helloworld_cpp` 目录中找到并启动 `helloworld`。

如果没有 `install(TARGETS ...)` 配置，程序虽然可能编译成功，但 `ros2 run` 无法在功能包的标准安装目录中找到它。

### 4. `rclcpp` 依赖的作用

源代码使用了 `rclcpp`，因此 `CMakeLists.txt` 需要查找依赖：

```cmake
find_package(rclcpp REQUIRED)
```

并将它关联到 `helloworld` 可执行文件：

```cmake
ament_target_dependencies(
  helloworld
  "rclcpp"
)
```

`package.xml` 中也声明了运行和编译所需的依赖：

```xml
<depend>rclcpp</depend>
```

### 5. 命令执行后的代码流程

`ros2 run` 启动可执行文件后，程序从 `main()` 函数开始执行：

```cpp
int main(int argc, char **argv)
{
    rclcpp::init(argc, argv);
    auto node = rclcpp::Node::make_shared("hello_world_node");
    RCLCPP_INFO(node->get_logger(), "hello world!");
    rclcpp::shutdown();
    return 0;
}
```

整体过程为：

```text
ros2 run
   ↓
查找 pkg01_helloworld_cpp 功能包
   ↓
查找 helloworld 可执行文件
   ↓
启动程序并进入 main() 函数
   ↓
初始化 ROS 2
   ↓
创建 hello_world_node 节点
   ↓
输出 hello world!
   ↓
关闭 ROS 2，程序结束
```

### 6. 三个名称的区别

| 名称 | 定义位置 | 作用 |
| --- | --- | --- |
| `pkg01_helloworld_cpp` | `<name>` 和 `project()` | ROS 2 功能包名称 |
| `helloworld` | `add_executable()` | 编译后的可执行文件名称 |
| `hello_world_node` | `Node::make_shared()` | 程序运行时的 ROS 2 节点名称 |

运行命令使用的是“功能包名称 + 可执行文件名称”：

```bash
ros2 run pkg01_helloworld_cpp helloworld
```

而 `hello_world_node` 是程序启动后注册到 ROS 2 图中的节点名称，不是 `ros2 run` 命令的参数。由于该程序没有调用 `rclcpp::spin()`，节点输出日志后会立即退出。

## 问题 3：为什么继承 `rclcpp::Node` 后就可以创建 ROS 2 节点

### 示例代码

```cpp
#include "rclcpp/rclcpp.hpp"

class MyNode : public rclcpp::Node
{
public:
    MyNode() : rclcpp::Node("node_name")
    {
        RCLCPP_INFO(this->get_logger(), "hello world!");
    }
};

int main(int argc, char *argv[])
{
    rclcpp::init(argc, argv);
    auto node = std::make_shared<MyNode>();
    rclcpp::shutdown();
    return 0;
}
```

### 1. `rclcpp::Node` 是 ROS 2 节点基类

`rclcpp::Node` 封装了 ROS 2 节点的核心能力，例如：

- 节点名称和命名空间；
- 日志记录；
- 发布器和订阅器；
- 服务端和客户端；
- 定时器和参数；
- ROS 2 通信资源的管理。

类的定义：

```cpp
class MyNode : public rclcpp::Node
```

表示 `MyNode` 公开继承 `rclcpp::Node`，也就是形成了“`MyNode` 是一种 `rclcpp::Node`”的关系。`MyNode` 对象不仅包含自己定义的内容，还包含完整的 `rclcpp::Node` 基类部分。

### 2. 基类构造函数创建了节点

`MyNode` 构造函数中的初始化列表为：

```cpp
MyNode() : rclcpp::Node("node_name")
```

这表示创建 `MyNode` 时，先调用 `rclcpp::Node` 的构造函数，并把 `node_name` 作为节点名称传入。真正完成 ROS 2 节点基础初始化的仍然是 `rclcpp::Node` 基类。

C++ 构造对象时会先构造基类，再执行派生类的构造函数体，因此顺序为：

```text
调用 std::make_shared<MyNode>()
                ↓
调用 rclcpp::Node("node_name")
                ↓
初始化 ROS 2 节点的基础能力
                ↓
执行 MyNode 构造函数体
                ↓
输出 hello world!
```

示例中也可以写成 `MyNode() : Node("node_name")`，但使用完整名称 `rclcpp::Node` 更清晰。

### 3. 为什么可以调用 `get_logger()`

`get_logger()` 是 `rclcpp::Node` 提供的公有成员函数。由于 `MyNode` 使用了公开继承：

```cpp
class MyNode : public rclcpp::Node
```

所以 `MyNode` 可以使用基类的公有接口。下面两种写法都可以：

```cpp
RCLCPP_INFO(this->get_logger(), "hello world!");
```

```cpp
RCLCPP_INFO(get_logger(), "hello world!");
```

`this` 是指向当前 `MyNode` 对象的指针。显式写出 `this->` 可以更清楚地表示调用的是当前节点对象的方法。

### 4. `std::make_shared<MyNode>()` 做了什么

```cpp
auto node = std::make_shared<MyNode>();
```

这条语句会创建一个 `MyNode` 对象，调用其构造函数，并使用智能指针管理对象的生命周期。`node` 的类型为：

```cpp
std::shared_ptr<MyNode>
```

因为 `MyNode` 公开继承了 `rclcpp::Node`，所以它可以在需要 ROS 2 节点的地方使用，例如：

```cpp
rclcpp::spin(node);
```

### 5. 继承方式的优点

直接创建 `rclcpp::Node` 和继承 `rclcpp::Node` 都是合法的 ROS 2 写法。直接创建方式并不是错误的：

```cpp
auto node = rclcpp::Node::make_shared("node_name");
```

对于只输出一条日志的简单程序，这种写法已经足够。当节点包含发布器、订阅器、定时器、参数和回调函数时，继承方式可以把节点的数据和行为封装到同一个类中，使代码更容易维护和扩展。

```cpp
class MyNode : public rclcpp::Node
{
public:
    MyNode() : rclcpp::Node("node_name")
    {
        // 创建发布器、订阅器和定时器等
    }

private:
    // 回调函数
    // 发布器成员变量
    // 订阅器成员变量
    // 定时器成员变量
};
```

继承方式的主要优点是：

- 将节点的数据和功能封装在一起；
- 避免将大量业务代码堆积在 `main()` 函数中；
- 方便管理发布器、订阅器和定时器等成员对象；
- 提高代码的可读性、复用性和可扩展性。

### 6. 当前示例为什么会立即退出

当前代码创建 `MyNode` 后立即执行了：

```cpp
rclcpp::shutdown();
```

程序没有调用 `rclcpp::spin()`，因此只会在 `MyNode` 构造函数中输出一次日志，然后立即关闭 ROS 2 并结束。

如果节点需要持续处理订阅、定时器或服务回调，应改为：

```cpp
int main(int argc, char *argv[])
{
    rclcpp::init(argc, argv);

    auto node = std::make_shared<MyNode>();
    rclcpp::spin(node);

    rclcpp::shutdown();
    return 0;
}
```

### 总结

继承方式能够创建节点，是因为创建 `MyNode` 时会先构造其 `rclcpp::Node` 基类部分。`rclcpp::Node` 负责完成 ROS 2 节点的基础初始化，`MyNode` 则用于封装和扩展具体的业务功能。

## 问题 4：发布者代码为什么标红

主要原因是相关成员没有声明，或者缺少头文件。

```cpp
#include <chrono>
#include <functional>

rclcpp::TimerBase::SharedPtr timer_;
rclcpp::Publisher<std_msgs::msg::String>::SharedPtr publisher_;
std::size_t count_;
```

还需要定义 `timer_callback()`，并删除不存在的类析构函数。`CMakeLists.txt` 中需要为源文件配置 `add_executable()`、`ament_target_dependencies()` 和 `install()`。

## 问题 5：构造函数的两种排版有什么区别

```cpp
MinimalPublisher() : Node("minimal_publisher"), count_(0)
```

与：

```cpp
MinimalPublisher()
    : Node("minimal_publisher"), count_(0)
```

功能完全相同，只有换行、空格和注释等排版区别。第二种更易读。

## 问题 6：定时器代码的作用

```cpp
timer_ = this->create_wall_timer(
    500ms,
    std::bind(&MinimalPublisher::timer_callback, this));
```

- `500ms`：每 0.5 秒触发一次。
- 第二个参数：触发时调用当前对象的 `timer_callback()`。
- `timer_`：保存定时器，防止它被提前释放。

## 问题 7：成员变量的作用

```cpp
rclcpp::TimerBase::SharedPtr timer_;
rclcpp::Publisher<std_msgs::msg::String>::SharedPtr publisher_;
std::size_t count_;
```

- `timer_`：定时器智能指针。
- `publisher_`：字符串消息发布器智能指针。
- `count_`：消息发布次数计数器。

末尾下划线是“类成员变量”的命名习惯，与是否为智能指针无关。

```cpp
count_(0)
```

表示在构造对象时将成员变量 `count_` 初始化为 `0`。

## 问题 8：`rclcpp::spin()` 是否会发送数据

```cpp
rclcpp::spin(std::make_shared<MinimalPublisher>());
```

`std::make_shared` 创建节点对象；`spin()` 让节点持续运行并处理回调。`spin()` 不直接发送数据，而是在定时器到期时调用 `timer_callback()`，再由回调函数执行发布。

## 问题 9：如何组织并发布消息

```cpp
auto message = std_msgs::msg::String();
message.data = "Hello, world! " + std::to_string(count_++);
RCLCPP_INFO(this->get_logger(), "发布的消息：'%s'", message.data.c_str());
publisher_->publish(message);
```

- 创建字符串消息。
- 设置 `data`，并在每次发布后将 `count_` 加 1。
- 在终端输出日志。
- 通过 `publisher_` 发布消息。

## 问题 10：订阅器代码的作用

```cpp
subscription_ = this->create_subscription<std_msgs::msg::String>(
    "topic",
    10,
    std::bind(
        &MinimalSubscriber::topic_callback,
        this,
        std::placeholders::_1));
```

- `std_msgs::msg::String`：订阅的消息类型。
- `"topic"`：话题名称。
- `10`：QoS 队列深度。
- 最后一个参数：收到消息时调用 `topic_callback()`。

注意正确拼写为 `MinimalSubscriber`、`create_subscription` 和 `subscription_`。

## 问题 11：`std::bind` 和 `_1`、`_2` 是什么

`std::bind` 用于绑定要调用的函数、对象和参数：

```cpp
std::bind(
    &MinimalSubscriber::topic_callback,
    this,
    std::placeholders::_1)
```

- 第一个参数：要调用的成员函数。
- `this`：调用函数的当前对象。
- `_1`：将调用时传入的第一个参数传给回调函数。
- `_2`：表示调用时传入的第二个参数。

写成 `_2, _1` 会将两个参数的传递顺序交换；只有调用者确实提供两个参数，且交换后类型仍匹配时才能这样写。

## 问题 12：回调函数中的 `&` 和两个 `const`

```cpp
void topic_callback(const std_msgs::msg::String &msg) const
```

- `&`：以引用方式接收消息，避免复制。
- 前面的 `const`：函数内不能修改 `msg`。
- 后面的 `const`：该成员函数不能修改当前对象的普通成员变量。


## 问题 15：运行节点时提示 `Package 'cpp01_topic' not found`

### 问题现象

在 `ws01_plumbing` 工作空间中执行：

```bash
ros2 run cpp01_topic demo01_talker_str
```

出现：

```text
Package 'cpp01_topic' not found
```

### 问题原因

当前目录中存在 `src/cpp01_topic`，不代表 ROS 2 已经能够找到这个功能包。`ros2 run` 查找的是已经成功安装并通过环境脚本注册的功能包。

本次问题包含两个原因：

1. `cpp01_topic` 上一次没有编译成功。构建日志中出现了 `ModuleNotFoundError: No module named 'catkin_pkg'`，因此安装过程不完整。
2. 即使功能包已经编译成功，新终端中也需要执行 `source install/setup.bash`，才能把当前工作空间加入 ROS 2 的搜索路径。

当终端处于 Conda 的 `(base)` 环境时，CMake 选中了 Miniconda Python，而 ROS 2 Humble 所需的 `catkin_pkg` 位于系统 Python 环境中。这部分原因与“问题 1”相同。

### 解决方法

```bash
cd /home/luvbot-2/ros2_learning/My_code/ws01_plumbing

conda deactivate
source /opt/ros/humble/setup.bash
which python3

colcon build --packages-up-to cpp01_topic --cmake-clean-cache
source install/setup.bash
```

`which python3` 应该输出：

```text
/usr/bin/python3
```

这里使用 `--packages-up-to cpp01_topic`，不仅会编译 `cpp01_topic`，也会先编译它依赖的 `base_interfaces_demo`。

编译成功后可以进行检查：

```bash
ros2 pkg prefix cpp01_topic
ros2 pkg executables cpp01_topic
```

正常情况下会看到：

```text
cpp01_topic demo01_talker_str
cpp01_topic demo02_listener_str
```

然后运行：

```bash
ros2 run cpp01_topic demo01_talker_str
```

注意：进入工作空间目录本身不会自动加载该工作空间。每次打开新终端后都需要加载 ROS 2 和工作空间环境：

```bash
source /opt/ros/humble/setup.bash
source /home/luvbot-2/ros2_learning/My_code/ws01_plumbing/install/setup.bash
```

## 问题 16：执行 `source install/setup.bash` 时提示缺少 `local_setup.bash`

### 问题现象

```bash
source install/setup.bash
```

出现：

```text
not found: "/home/luvbot-2/ros2_learning/My_code/ws01_plumbing/install/cpp01_topic/share/cpp01_topic/local_setup.bash"
```

### 问题原因

这是上一次构建中途失败留下的“不完整安装目录”。`install/cpp01_topic` 中已经生成了一部分环境文件，例如 `package.bash`，但构建在 CMake 配置或 C++ 编译阶段失败，因此没有完成安装，也没有生成 `local_setup.bash`。

顶层的 `install/setup.bash` 会尝试依次加载各功能包的环境脚本。当它加载这个不完整的功能包时，就会报告文件不存在。

因此，该错误不是 `source` 命令语法错误，也不应该通过手动创建一个空的 `local_setup.bash` 来处理。真正需要解决的是前面的构建失败。

### 解决方法

先不要加载损坏的工作空间，只加载 ROS 2 基础环境，然后清理 CMake 缓存并重新构建：

```bash
cd /home/luvbot-2/ros2_learning/My_code/ws01_plumbing

conda deactivate
source /opt/ros/humble/setup.bash
colcon build --packages-up-to cpp01_topic --cmake-clean-cache
```

必须看到类似以下总结，才表示构建成功：


## 问题 17：`create_publisher<Student>()` 提示 `template argument 1 is invalid`

### 问题现象

编译发布者时出现：

```text
error: template argument 1 is invalid
publisher_ = this->create_publisher<Student>("topic_stu", 10);
```

同时还出现：

```text
warning: no return statement in function returning non-void
```

### 问题原因

`create_publisher<MessageType>()` 的模板参数必须是一个有效的 ROS 2 消息类型。这里并不是 `create_publisher()` 本身有问题，而是编译器无法把 `Student` 识别为有效类型。

发布端代码中存在以下问题：

1. 没有包含自定义消息生成的头文件：

   ```cpp
   #include "base_interfaces_demo/msg/student.hpp"
   ```

2. 错误地把 `Student` 类型当成了命名空间：

   ```cpp
   // 错误
   using namespace base_interfaces_demo::msg::Student;

   // 正确
   using base_interfaces_demo::msg::Student;
   ```

3. 构造函数初始化列表使用了中文全角冒号 `：`，而 C++ 要求使用英文半角冒号 `:`。
4. 节点名称使用了字符单引号，字符串应使用双引号。
5. `StudentPublisher` 类定义结束后缺少分号 `;`。

因为前面的语法错误破坏了编译器对代码结构的解析，所以还产生了“非 `void` 函数没有返回值”等连带错误。修复前面的语法问题后，该警告也会消失。

### 发布端正确写法

```cpp
#include "rclcpp/rclcpp.hpp"
#include "base_interfaces_demo/msg/student.hpp"

using namespace std::chrono_literals;
using base_interfaces_demo::msg::Student;

class StudentPublisher : public rclcpp::Node
{
private:
    rclcpp::TimerBase::SharedPtr timer_;
    rclcpp::Publisher<Student>::SharedPtr publisher_;
    std::size_t count_;

    void timer_callback()
    {
        auto student = Student();
        student.name = "张三";
        student.age = count_++;
        student.height = 1.78;

        RCLCPP_INFO(
            this->get_logger(),
            "学生信息：name=%s, age=%d, height=%.2f",
            student.name.c_str(), student.age, student.height);

        publisher_->publish(student);
    }

public:
    StudentPublisher()
        : Node("StudentPublisher"), count_(0)
    {
        publisher_ = this->create_publisher<Student>("topic_stu", 10);
        timer_ = this->create_wall_timer(
            500ms,
            std::bind(&StudentPublisher::timer_callback, this));
    }
};
```

### 订阅端的相关问题

订阅端也要使用完全相同的消息类型，否则发布者和订阅者不能建立通信：

```cpp
#include "base_interfaces_demo/msg/student.hpp"

using base_interfaces_demo::msg::Student;

rclcpp::Subscription<Student>::SharedPtr subscriber_;

subscriber_ = this->create_subscription<Student>(
    "topic_stu",
    10,
    std::bind(&StudentSubscriber::topic_callback, this, std::placeholders::_1));
```

本次订阅端还存在以下错误：

- 头文件包名误写为 `base_inferfaces_demo`，正确名称是 `base_interfaces_demo`；
- `create_subscription` 的模板类型误写为 `std_msgs::msg::String`，应该是 `Student`；
- 构造函数也使用了中文全角冒号；
- 类定义结尾缺少分号；
- 日志格式符与字段类型不匹配。

`Student.msg` 中的字段为：

```text
string name
int32 age
float64 height
```

因此日志格式符应分别使用 `%s`、`%d` 和 `%.2f`：

```cpp
RCLCPP_INFO(
    this->get_logger(),
    "学生信息：姓名='%s', 年龄=%d, 身高=%.2f",
    msg.name.c_str(), msg.age, msg.height);
```
